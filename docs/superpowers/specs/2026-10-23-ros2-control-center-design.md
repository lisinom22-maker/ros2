# ROS 2 控制中心设计

## 意图

为本机 Ubuntu 22.04 + ROS 2 Humble 提供一个面向日常使用的桌面控制中心。用户双击桌面图标后，可以明确看到 ROS 环境是否可用，直接启动或停止常用工具，并查看当前 ROS 节点、话题和服务。

## 目标

- 独立创建 PyQt5 桌面应用，不改动现有 `~/ros2-system-status` 项目。
- 首页显示 ROS 2 Humble 环境状态、受管工具运行数量和最近操作结果。
- 管理小乌龟模拟器、键盘控制、RViz2、rqt 和现有系统状态监控。
- 每个工具显示未运行、启动中、运行中、停止中或异常状态，并提供启动、停止和重新启动操作。
- 提供节点、话题、服务三个可刷新查看页，以及最近操作和错误日志。
- 提供“一键创建工作空间”：默认路径为 `~/ros2_ws`，创建标准 `src/` 结构；允许改选位置，绝不覆盖已有文件，并提供打开文件夹与在终端开始构建的入口。
- 提供“停止全部”；只停止由控制中心启动的进程。
- 关闭窗口时，如有受管进程仍在运行，让用户选择停止进程、保留后台运行或取消关闭。
- 在 `~/桌面` 放置可双击的启动入口。

## 非目标

- 不替代完整 IDE、终端或 ROS 2 教程。
- 不管理从其他终端或其他应用启动的进程。
- 不安装或升级 ROS 2，不执行需要 `sudo` 的操作。
- 不在首版加入 Gazebo、Nav2、内嵌构建流水线或任意命令编辑器；构建入口只在独立终端运行标准命令。
- 不生成示例包，也不替用户决定 Python/C++ 包类型；工作空间首版只负责安全创建标准目录并提供显式构建入口。

## 约束与交互

- 使用系统 Python 3.10、PyQt5 和 ROS 2 Humble 已有安装，不新增大型依赖。
- 所有 ROS 命令通过 `/opt/ros/humble/setup.bash` 加载环境；系统状态监控额外加载 `~/ros2-system-status/install/setup.bash`。
- 键盘控制在独立 GNOME Terminal 中运行；其余 GUI 工具直接打开。
- 启动、停止和失败必须立即给出可见反馈；耗时的 ROS 图查询不得冻结窗口。
- 停止先发送 SIGINT，超时后再终止，仅作用于控制中心记录的 PID/进程组。
- 创建工作空间时，目标不存在则创建 `<workspace>/src`；目标已是含 `src/` 的工作空间则视为可用；目标为非空普通目录且不含 `src/` 时拒绝修改。
- 界面支持键盘焦点、可访问名称和清晰文字；动效保持克制，并尊重系统减少动态效果偏好。

## 方案记录

- 选择独立 PyQt5 控制中心：与现有监控解耦，便于以后增加工具。
- 不选择扩展现有监控：避免把系统指标展示与工具进程管理混在一起。
- 不选择纯快捷按钮：无法可靠呈现状态、停止受管进程或集中查看错误。

## 文件位置

- 源码：`~/ros2-control-center`
- 桌面入口：`~/桌面/ROS2 控制中心.desktop`
- 用户日志与运行状态：`~/.local/state/ros2-control-center/`
