# ROS2 控制中心

面向 Ubuntu 22.04、ROS 2 Humble 的独立 PyQt5 桌面应用。管理小乌龟模拟器、键盘控制、RViz2、rqt 和已有的系统状态监控，并显示节点、话题、服务及工具日志。

使用系统 `/usr/bin/python3` 和已安装的 PyQt5、ROS 2 Humble、GNOME Terminal、Nautilus、colcon。系统状态监控沿用 `~/ros2-system-status/install/setup.bash`。本项目不安装或升级这些依赖。

在项目目录执行：

```bash
bash scripts/install_desktop.sh
```

安装不需要 sudo，可重复运行以更新应用。默认安装位置：

- 启动器：`~/.local/bin/ros2-control-center`
- 独立运行副本：`~/.local/share/ros2-control-center/ros2_control_center/`
- 桌面图标：`~/桌面/ROS2 控制中心.desktop`
- 启动日志：`~/.local/state/ros2-control-center/startup.log`

安装器遵循 `XDG_DATA_HOME`、`XDG_CONFIG_HOME/user-dirs.dirs` 和可选的 `XDG_DESKTOP_DIR`；启动日志遵循 `XDG_STATE_HOME`。只替换本应用文件，不修改其他桌面入口或现有系统监控。安装副本与源码目录独立，删除开发 worktree 后仍可启动。支持文件管理器信任元数据时自动设置；否则右键桌面图标选择“允许启动”。

双击图标打开窗口。工具按钮提供启动、停止和重新启动；“停止全部”只停止本应用启动的进程。关闭窗口时可以停止工具、保留工具后台运行或取消关闭。键盘控制在独立终端中接收按键。ROS 图页面通过刷新获取节点、话题和服务。

默认工作空间为 `~/ros2_ws`。创建操作仅创建标准 `src/` 目录，已有工作空间可直接打开；非空且没有 `src/` 的目录会被拒绝。构建按钮需要明确点击，在独立终端执行标准 colcon 构建。终端会显示成功或失败及退出码，按 Enter 后关闭；切换目录或加载 ROS 环境失败时也会保留结果。

## 按按钮完成一个 ROS 2 项目

窗口顶部的“工作空间与功能包”区域会代做环境加载和常见命令。主界面只保留操作控件；右上角“使用说明”按钮可打开详细步骤。只有节点中的具体业务代码需要自己在 VS Code 中写。

| 顺序 | 在界面上怎么按 | 完成后会怎样 |
| --- | --- | --- |
| 1. 工作空间 | 点“按名称新建…”并在弹窗输入 `my_robot_ws`；已有空间可从“已用过”选择，或点“选择工作空间…”在窗口里选。也可手填路径后点“创建工作空间”。 | 创建或确认 `src/`；不同路径就是互不影响的多个工作空间。 |
| 2. 写代码位置 | 点“选择文件夹…”从当前工作空间的 `src` 中选；或点“创建文件夹…”，在弹窗输入名字并确认。 | 当前文件夹会显示在界面上；新文件夹会自动被选中。可重复创建不同名字的文件夹。 |
| 3. 功能包 | 点击“设置并创建功能包…”，在弹窗输入包名（例如 `my_robot`），选择 **Python** 或 **C++**，勾选所需 ROS 库，再点“创建功能包”。 | 当前系统的 ROS 环境是 Humble。功能包建在选定文件夹内，并生成可运行示例节点；所选库会加入依赖和源码导入。整个工作空间内重名的包会被拒绝。 |
| 4. 写代码 | 新建功能包后会自动在 VS Code 打开示例源码。以后可点击“选择源码文件…”从窗口选文件，选中后直接跳到 VS Code；也可点“编辑选中包源码”。 | 编辑器打开对应文件，修改后保存。还可点“打开此文件夹”查看选定目录。 |
| 5. 构建 | 点击“在终端构建”，等待独立终端显示 `Summary: ... package finished` 或明确的失败信息。 | 自动加载 ROS 2 Humble 环境并执行 `colcon build --symlink-install`；构建失败时修正代码后重新点击。 |
| 6. 运行 | 构建成功后点击“刷新可运行节点”，选择节点并点击“运行节点”。 | 控制中心加载工作空间环境并运行节点；输出显示在窗口中。“停止节点”可结束当前节点。 |
| 7. 看话题 | 如果代码发布了话题，先运行节点，输入实际话题名（例如 `/chatter`），点击“查看话题”。 | 新终端执行 `ros2 topic echo`；按 **Ctrl+C** 停止查看。生成的简单示例节点不一定发布话题，必须按自己代码中的话题名填写。 |

“打开文件夹”“在终端构建”和“查看话题”会打开独立程序，不受顶部“停止全部”按钮控制。节点由控制中心运行，可点击“停止节点”；关闭控制中心也会停止该节点。话题终端可按 Ctrl+C 停止查看。更换工作空间时，功能包和可运行节点列表只显示当前路径中的内容；构建后要点击“刷新可运行节点”。

创建功能包时，弹窗会显示本机配置的 ROS 2 Humble 环境，并提供已安装的常见 ROS 库：`std_msgs`（基础消息）、`geometry_msgs`（位置与速度）、`sensor_msgs`（传感器）、`nav_msgs`（导航）、`tf2_ros`（坐标变换）。Python 会自动带上 `rclpy`，C++ 会自动带上 `rclcpp`；勾选的库会写进 `package.xml`，并加入示例源码的导入或头文件。这里是**选择已有库**，不会联网安装新库。普通代码文件夹可用中文和空格命名；ROS 功能包名仍须用小写英文、数字和下划线。

只检查环境（不启动工具、不创建或构建工作空间）：

```bash
QT_QPA_PLATFORM=offscreen ~/.local/bin/ros2-control-center --smoke-test
cat ~/.local/state/ros2-control-center/startup.log
```

开发时运行和测试：

```bash
PYTHONPATH=src /usr/bin/python3 -m ros2_control_center.app
QT_QPA_PLATFORM=offscreen /usr/bin/python3 -m pytest -q
```

安装测试使用临时 HOME 和 XDG 目录，不触碰实际桌面。移除应用时仅删除上述启动器、运行副本和本应用桌面图标；日志可按需保留。
